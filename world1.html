Before you start

Get your ship ready

We'll write Python in a free app called Pydroid 3. Ask a grown-up to help with these steps the first time.

  1. Open the Google Play Store, search for Pydroid 3, and install it. It's free (it shows some ads).
  2. Open Pydroid 3. Let it finish setting up, which can take a minute the first time.
  3. The big white area is the editor. That's where you type code.
  4. Tap the big ▶ play button to run your code. The answer appears on a black screen called the terminal.
  5. To go back to your code, use the phone's back button or the arrow at the top.
  6. To start a new program, clear the editor. To keep one, use the folder menu → Save and give it a name like lesson1.

Important phone trick: turn off autocorrect

Phone keyboards try to "help" by changing print into Print, or by changing straight quotes " into curly ones “ ”. Python doesn't understand those. Open your phone's Settings → Keyboard and turn off auto-correct, auto-capitalization and smart punctuation if you see it.

Pydroid also has a row of extra keys above the keyboard with symbols like ( ) " # * :. Use them, they're faster!

Lesson 1 · About 30 minutes

Hello, Mission Control!

Story: Py-Bot just woke up after a long sleep in deep space. Its speaker is working, but it doesn't know what to say. You need to give it its very first words!

The big idea: print() is Py-Bot's mouth

When you write print("something"), Python shows something on the screen. The words go inside quotes " ". Quotes tell Python: "This is text. Say it exactly like this." Programmers call text in quotes a string, because it's like letters threaded on a string, one after another.

print( "Hello!" )
  │     └──┬──┘
  │        └─ the words to say, inside quotes
  └─ the command: "show this on the screen"

Type it and run it +10 XP

Type these two lines. You don't have to type the grey notes after the #; they're just explanations for you.

print("Hello, Mission Control!")   # Py-Bot's first words
print("I am ready to fly!")        # a second line of words
Hello, Mission Control!
I am ready to fly!

Change it! +10 XP

Experiment. Guess what will happen before you tap ▶.

  • Change Mission Control to your own name.
  • Use single quotes instead: print('Hi!'). Does it still work? (Yes! Both kinds work. Just use the same kind at both ends.)
  • Remove the quotes: print(Hi). You'll get a red error. That's okay! An error is just a clue from the computer. Without quotes, Python thinks Hi is a name it should already know.

No phone needed · 10 minutes

Game: Robot Commander

One person is Py-Bot. Everyone else writes commands on scraps of paper, like print("Hop on one foot") or print("Say BANANA").

  1. Line up the paper commands in order. That's your program!
  2. Py-Bot does each command, top to bottom, exactly as written. Nothing more, nothing less.
  3. If a command has a mistake (a capital P, missing quotes or a missing bracket), Py-Bot says "ERROR! BEEP BOOP!" and freezes until the writer fixes it.
  4. Take turns being Py-Bot.

What you're learning: computers do exactly what you write, in order, and they're very picky about spelling.

Lesson 2 · About 30 minutes

Countdown!

Story: The rocket is fueled and ready. Mission Control needs Py-Bot to do the countdown, but the numbers have to come in the right order, or the rocket will get very confused!

The big idea: Python reads from top to bottom

Python runs your code one line at a time, starting at the top, like reading a recipe. If you change the order of the lines, you change the order things happen.

Also: any line that starts with # is a comment. Python skips it. It's a secret note for humans.

Type it and run it +10 XP

# Launch program by the Star Crew
print("3...")
print("2...")
print("1...")
print()
print("BLAST OFF! 🚀")
3...
2...
1...

BLAST OFF! 🚀

See the empty line before BLAST OFF? That's the print() with nothing inside. And the comment line on top didn't show up at all!

  • Make it start from 5 instead of 3.
  • Add your own comment, like # made by Leo. Does it show up on screen?

Lesson 3 · About 30 minutes

Space Calculator

Story: We're in space! Now the crew needs answers fast: How far is the Moon? How many snacks do we need? Good news: Py-Bot is a super-fast calculator.

The big idea: no quotes means "do the math"

If you put numbers in print() without quotes, Python works out the answer. With quotes, it just repeats the text.

MathPython symbolExample
Plus+2 + 3
Minus-10 - 4
Times* (a star, not x!)3 * 4
Divide/ (a slash)10 / 2

Type it and run it +10 XP

print(2 + 3)       # adds
print(10 - 4)      # subtracts
print(3 * 4)       # times uses a star
print(10 / 2)      # divide uses a slash
print("2 + 3")     # in quotes it's just text!
5
6
12
5.0
2 + 3

Why 5.0? When Python divides, it always gives an answer with a dot, in case the answer is something like 3.5 (three and a half).

Change it! +10 XP

  • The Moon is about 384400 kilometers away. How far is there and back? Try print(384400 * 2).
  • Try print(7 / 2). What does the dot mean now?
  • Surprise test: what happens if you write a big number with a comma, like print(384,400)? (Python thinks the comma means "two separate numbers"! So write big numbers without commas.)

Starship Art Studio

Story: The ship's walls are boring and grey. Py-Bot wants to decorate! There's no paint in space, but you can draw pictures using letters and symbols. This is called text art.

The big idea: stack lines to make a picture, and multiply text

Error message decoder

Red text isn't a disaster. It's Python giving you a clue! Read the last line of the error first. It also tells you which line number has the problem.

The error says…What it meansHow to fix it
NameError: name 'Print' is not definedPython doesn't know that word. Often it's a capital letter or a typo.Use a small print. Check spelling.
NameError: name 'Hi' is not definedYou forgot the quotes around your words.print("Hi")
SyntaxError: unterminated string literalA quote is missing at the end of your words.Make sure there's a " at both ends.
SyntaxError: '(' was never closedA bracket is missing at the end.Every ( needs a ).
SyntaxError: invalid character '“'The phone used curly "smart" quotes.Use the straight " key from Pydroid's extra keys, and turn off smart punctuation.
SyntaxError: invalid syntaxSomething is written in a way Python doesn't understand, like x for times.Look near where the error points. Use * for times.
TypeError: can't multiply sequence by non-int of type 'str'You tried to multiply text by text.The number must not be in quotes: "*" * 5
For grown-ups and group leaders

Leader's guide and answer key

You don't need to know how to code to run this. Each lesson takes about 30 minutes. Do one lesson per session, or two short ones. Let learners try first, and only open the answer key when they're truly stuck.

How to run a session (30–40 minutes)
  1. Warm-up (3 min): Ask "What did Py-Bot learn last time?"
  2. Story and big idea (5 min): Read them aloud together.
  3. Type it and run it, then Change it (10 min): Everyone types. Celebrate errors: "Great, a clue!"
  4. Challenges (10 min): Each learner picks their own level. Fast finishers can try the next level or help others by asking questions, not by typing for them.
  5. Bug hunt, pair activity and quiz (7 min).
  6. Show and tell (3 min): Everyone shows one thing they made. Clap for each one!
How to help without giving the answer
  • "What did you expect to happen? What happened instead?"
  • "What does the last line of the red error say? Which line number?"
  • "Read your line out loud to me, letter by letter."
  • "Can you find the part in the lesson that does something like this?"
  • Point to the hints on the page before showing the answer.
Sharing phones, different speeds and scorekeeping
  • Sharing one phone: use Driver/Navigator for everything. Swap every 5 minutes or at each new challenge. Pick the right player in the top bar before tapping a task.
  • Separate phones: each learner opens this page on their own phone and adds just themselves. Compare XP at show-and-tell.
  • Scores are saved in the phone's browser. Clearing browsing data will erase them, so you could also keep a paper tally as a backup.
  • Different speeds: challenge levels let everyone work on the same idea. Nobody is behind; they're just choosing a different level.
  • Keep competition kind: XP rewards trying, fixing bugs and teamwork, not just speed. Consider small extra awards at show-and-tell: "Most creative," "Best bug hunter," "Kindest helper."
  • Honesty: learners tap their own "Done" buttons. You can glance at the screen to confirm.
