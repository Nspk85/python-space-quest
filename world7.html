Lesson 1 · About 40 minutes

Plan the Mission

Story: Real game studios don't start by typing code. They start with paper, pencils and big ideas! Today your crew becomes a game studio.

The big idea: plan first, then build a skeleton

On paper, answer these questions together:

  1. Title: what is the game called?
  2. Goal: how do you win? How do you lose?
  3. Parts: what are the rooms, levels or rounds? (3 to 5 is plenty.)
  4. Boxes and lists: what does the game need to remember? (health, score, a backpack list…)
  5. Jobs: who builds which part?

Then write a skeleton: the spells (functions) with simple placeholder insides. It runs straight away, even though it isn't finished. Each person then fills in their own spell.

Game: Playtest Party

Real game makers let other people test their games. Do this after Lesson 3 or 4:

  1. Swap games with another pair (or act out your game on paper, with one person reading the rooms aloud).

Lesson 2 · 1 or 2 sessions

Build the Parts

Story: Each crew member builds one room of the space station. Your room is your own little program: it can ask questions, use random surprises, and add things to the backpack.

The big idea: build one part, and test it on its own

Each room is a spell that takes the backpack list and returns how much health changes: -1 for ouch, 0 for nothing, 1 for a bonus. Before joining the team code, give your room a test drive on its own.

Fun fact: when a spell appends to the backpack list, the item stays in the backpack after the spell ends. That's how rooms share items!

Type it and run it: the kitchen +10 XP

def kitchen(backpack):

Lesson 3 · 1 or 2 sessions

Put It Together

Story: All the rooms are built! Now the crew joins them into one game. This is where surprises happen, because parts that worked alone sometimes don't fit together. Time to test like a pro.

The big idea: join the parts, then test every path

  • Put everyone's room spells at the top, then the visit_room spell that picks the right room.
  • Test every path: try to win, try to lose, try silly answers.
  • Debug prints: if something's weird, add print("DEBUG health =", health) to peek inside your boxes. Delete it when you're done.

Type it and run it: the whole game +10 XP

# Space Station Rescue by Mia and Leo
import random

def show_title():
    print("=" * 30)
    print("   🛰️  SPACE STATION RESCUE")
    print("=" * 30)
    print("Find the power cell and get home safe!")

def show_status(health, backpack):
    print("❤️ Health:", health, "| 🎒", backpack)

def kitchen(backpack):
    print("🍳 The kitchen is a mess. Something glows in the fridge!")
    choice = input("Open the fridge? yes or no: ").lower()
    if choice == "yes":
        print("You find a torch! 🔦")
        backpack.append("torch")
        return 0
    else:
        print("You slip on a space noodle. Ouch!")
        return -1

def engine_room(backpack):
    print("⚙️ The engine room is very dark...")
    if "torch" in backpack:
        print("Your torch shows a power cell on the floor! 🔋")
        backpack.append("power cell")
        return 0
    else:
        print("You bump into a pipe in the dark. Ouch!")
        return -1

def control_room(backpack):
    print("🖥️ Alarms are ringing in the control room!")
    if random.randint(1, 2) == 1:
        print("A friendly robot gives you a health pack! ➕")
        return 1
    else:
        print("A spark zaps you! ⚡")
        return -1

def visit_room(room, backpack):
    if room == "kitchen":
        return kitchen(backpack)
    elif room == "engine room":
        return engine_room(backpack)
    else:
        return control_room(backpack)

show_title()
health = 3
backpack = []
rooms = ["kitchen", "engine room", "control room"]
for room in rooms:
    print()
    health = health + visit_room(room, backpack)
    show_status(health, backpack)
print()
if "power cell" in backpack and health > 0:
    print("🏆 You fixed the station and flew home. YOU WIN!")
else:
    print("💤 Mission failed... try a different path!")

  • Can you win? Can you lose?

For grown-ups and group leaders

Leader's guide and answer key: World 7

World 7 is about teamwork and process, not new Python. Plan for 4 to 6 sessions plus a Launch Day. Expect the "putting it together" step to be messy. That's normal, and it's the most valuable learning in the whole course.

Running the team project
  • Team size: 2 to 4 per game works best. One phone can hold the team's "main" code while others build rooms on their own phones.
  • Shared code: agree on the "contract" for every room spell (it takes backpack and returns a number). That's what makes the parts fit together.
  • Moving code between phones: copy from the Code Pad into a message or notes app, then paste on the main phone.
  • Keep scope small: 3 working rooms beat 10 broken ones. Extra ideas go on a "version 2" list.
  • Celebrate bugs: when parts don't fit, that's the real lesson. Use the testing checklist and debug prints.
  • Fairness: make sure everyone's room is in the final game and named in the credits.
